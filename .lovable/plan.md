## Этап 2. Админка на реальных данных (блоки 2–4)

- `/admin/cars`: список из `getCarsAdmin`, карточки с госномером, создание/редактирование в модальном окне, смена статуса (свободна/занята/мойка/ТО), удаление, загрузка фото через `uploadCarPhoto`.
- `/admin/bookings`: данные из `getBookingsAdmin` с фильтрами по статусу и датам, действия «Подтвердить / Выдать / Завершить / Отменить», автосинхронизация статуса авто.
- `/admin/clients`: `getClientsAdmin` — телефон, число заказов, сумма, блокировка клиента.
- `/admin/finance`: `getPaymentsAdmin` с диапазоном дат, KPI (выручка, средний чек, число оплат) и экспорт в Excel по реальным строкам.
- `/admin` дашборд: KPI, статусы парка и активные брони из БД.
- Все админ-страницы работают только после входа по паролю; при ошибке доступа — редирект на `/admin/login`.

## Этап 3. Кабинет клиента и вход по SMS (блоки 8, 5)

- Новый маршрут `/login`: ввод телефона → `requestOtp` → ввод кода → `loginWithOtp`, сессия в httpOnly cookie.
- `/profile` переводится на `getMyBookings`: текущая аренда, история, документы, избранное, выход из аккаунта. Без сессии — экран входа.
- Подписание договора `/contract/:id`: код из SMS через `confirmOtp`, фиксация `signed_at` и IP, статус брони «Подтверждена».
- Оплата `/payment/:id`: `startPayment` (ЮKassa; без ключей — демо-режим), возврат на профиль, статус обновляется вебхуком.

## Этап 4. Мобильная светлая тема по макетам

Приводим мобильные экраны к присланным скриншотам (белый фон, карточки с мягкой тенью, синий акцент, крупные заголовки):

- Каталог: строка поиска, чипы брендов, карточки с фото, характеристиками (объём, л.с., расход), ценой и кнопкой.
- Карточка оплаты: сводка авто, стоимость (аренда + залог), выбор способа оплаты, крупная кнопка «Оплатить».
- Подписание договора: резюме аренды, данные авто, чекбоксы согласий, поле кода, кнопка подписи, ссылка на PDF.
- Профиль: карточка «Текущая аренда» с госномером и адресом выдачи (Доватора, 11), статус договора, документы, история, нижняя навигация.
- Админка на мобиле: тот же светлый стиль, KPI-плитки, статусы парка, карточки броней, быстрые действия.

## Этап 5. Договор PDF (блок 6)

- Генерация договора в PDF на сервере с реквизитами ИП, данными авто, сроками, суммой и отметкой о подписании кодом из SMS; скачивание из договора и из профиля.

## Этап 6. Полная проверка

- Прогон сценариев в браузере: главная → каталог → карточка → бронирование → оплата → договор → профиль; вход в админку и все её разделы; светлая и тёмная темы, мобильный и десктоп.
- Проверка серверной части: подключение к БД, применение миграций, отсутствие ошибок в логах, ответ вебхука.
- Итоговый отчёт по всем 12 блокам промтов: выполнено / выполнено с заглушкой (SMS, ЮKassa, Яндекс OAuth) / требует ключей.

## Технические детали

- Ключи, которые понадобятся позже: `SMS_API_KEY` (SMSC), `YOOKASSA_SHOP_ID` + `YOOKASSA_SECRET_KEY`, `YANDEX_CLIENT_ID`/`YANDEX_CLIENT_SECRET`. До их появления работают заглушки: код OTP возвращается в ответе, оплата помечается успешной локально.
- Для PDF использовать библиотеку, совместимую с Node-сервером Nitro (`pdf-lib`), без нативных зависимостей.
- Все админ-функции защищены `requireAdmin()`, клиентские — cookie-сессией; входные данные валидируются Zod.
