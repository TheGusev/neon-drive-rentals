# Соответствие требованиям РКН + полная интеграция с ЮKassa

Цель: сайт nsk-rent.ru готов к проверке Роскомнадзора (152-ФЗ, 149-ФЗ, закон о рекламе/маркировке, требования к информации об ИП) и полностью интегрирован с ЮKassa — включая фискальные чеки 54-ФЗ, возвраты и webhook. Боевые ключи ЮKassa подставляются переменными окружения позже; до этого работает демо-режим (заглушка).

## 1. Юридический блок (РКН)

- **Согласие на обработку ПДн — отдельный документ** `/consent`: цели, перечень данных, срок, порядок отзыва, оператор (ИП Зажигаев И. Ю., ОГРНИП, ИНН, адрес).
- **Политика конфиденциальности** `/privacy` — дополнить: сведения о трансграничной передаче (отсутствует), локализация БД на территории РФ (242-ФЗ), перечень обработчиков (ЮKassa, Яндекс.Метрика, SMS-провайдер, хостинг), порядок ответа на обращения (30 дней), контакты ответственного за обработку ПДн, ссылка на реестр операторов.
- **Cookie-политика** `/cookies` + баннер согласия: категории cookie (технические/аналитические), кнопки «Принять» и «Только необходимые». Яндекс.Метрика подключается только после согласия на аналитические cookie.
- **Пользовательское соглашение / оферта** `/terms` — уточнить статус документа, порядок заключения договора аренды, оплату, депозит, отмену и возврат средств, претензионный порядок и подсудность.
- **Реквизиты ИП** — вывести в подвал на всех страницах: наименование, ОГРНИП, ИНН, адрес, телефон, e-mail, режим работы (уже частично есть — привести к единому обязательному составу).
- **Чекбоксы согласия** во всех формах, где собираются ПДн: регистрация, вход по SMS, бронирование, оплата, форма обратной связи. Несогласие блокирует отправку.
- **Фиксация согласия**: миграция `017_consents.sql` — таблица `consents` (тип согласия, версия документа, дата, IP, user-agent, телефон/e-mail, id клиента). Запись при регистрации, бронировании и принятии cookie-баннера.
- **Возрастная маркировка** и предупреждения: требования к арендатору (21+, стаж) выведены на видном месте на страницах брони.
- В `robots.txt`/`sitemap.xml` добавить новые страницы; в подвале — блок «Правовая информация» со всеми документами.

## 2. Полная интеграция с ЮKassa

- **Создание платежа** (`src/lib/yookassa.server.ts`): добавить в payload объект `receipt` по 54-ФЗ — покупатель (телефон и/или e-mail клиента), позиция «Аренда автомобиля <марка модель>, <даты>», количество, сумма, `vat_code: 1` (без НДС), `payment_subject: service`, `payment_mode: full_payment`, `tax_system_code: 2` (УСН доходы). Значения ставок вынести в переменные окружения с дефолтами.
- **Заглушка**: если `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY` не заданы — текущий stub-режим сохраняется, но теперь он логирует полный сформированный payload (включая receipt), чтобы после получения ключей ничего не менять в коде.
- **Webhook** `/api/public/yookassa-webhook`: обрабатывать события `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`; идемпотентность по `provider_id` + статусу, чтобы повторные уведомления не ломали бронь.
- **Возвраты**: серверная функция создания возврата через API ЮKassa + кнопка «Вернуть оплату» в админке на карточке платежа; статус платежа `refunded`, бронь — `cancelled`.
- **Статусы и сверка**: серверная функция «проверить платёж в ЮKassa» (poll по `provider_id`) на странице счёта и в админке — на случай, если webhook не дошёл.
- **Страница счёта** `/invoice/:id`: показывать позиции чека, сумму, статус, ссылку на повторную оплату и уведомление о том, что фискальный чек направлен ЮKassa на телефон/e-mail.
- **Логи платежей**: миграция `018_payment_events.sql` — таблица `payment_events` (сырое уведомление, статус, дата) для разбора спорных ситуаций; просмотр в админке.
- **Проверка подлинности уведомлений**: сохранить IP-фильтр, добавить возможность отключения через env для тестов и сверку суммы платежа с суммой брони перед активацией аренды.

## 3. Технические детали

- Новые env: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_TAX_SYSTEM_CODE` (по умолчанию 2), `YOOKASSA_VAT_CODE` (по умолчанию 1), `YOOKASSA_RETURN_URL_BASE` — задокументировать в `deploy/DEPLOY.md`.
- Миграции `017_consents.sql` и `018_payment_events.sql` — идемпотентные, применяются автоматически при старте (`migrations.server.ts`).
- Согласие на cookie хранится в `localStorage` + cookie; Яндекс.Метрика монтируется только при наличии согласия.
- Все новые серверные вызовы — через `createServerFn`, платёжные секреты читаются внутри `.handler()`.
- Проверка: typecheck, локальный прогон сценария «бронь → оплата (stub) → webhook → активная аренда → возврат», проверка чекбоксов и cookie-баннера на мобильной и десктопной версии.

## Ограничения

Боевую интеграцию с ЮKassa (реальные платежи, приход чеков) можно проверить только после выдачи ключей магазина и настройки URL уведомлений в личном кабинете ЮKassa на `https://nsk-rent.ru/api/public/yookassa-webhook`. До этого сценарий проверяется в демо-режиме.
