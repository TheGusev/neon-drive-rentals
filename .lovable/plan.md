# NSK-RENT: загрузка фото, синхронизация данных авто, редизайн админки и кабинета

## 1. Загрузка фото в форме авто (/admin/cars)

Вместо текстового поля «Ссылка на фото» — блок загрузки:
- Drag-and-drop зона + кнопка «Выбрать файл»; на телефоне `input type="file" accept="image/*" capture="environment"` (галерея/камера).
- Множественный выбор: сразу несколько фото за раз, галерея авто.
- Превью-миниатюры в форме: удаление, перетаскивание порядка, первое фото = обложка.
- Клиентское сжатие через canvas (максимальная сторона 1600 px, JPEG/WEBP ~0.82) перед отправкой.
- Валидация: только jpg/png/webp, до 5 МБ на файл, до 12 фото на авто.
- Сохранение: уже существующая серверная функция `uploadCarPhoto` (пишет в `public/assets/cars` через `uploads.server`), затем массив путей уходит в `updateCarImages` → колонка `cars.images` (JSONB). Тип колонки не меняем.
- Возможность добавить фото и по URL — оставляем как дополнительный ввод, а не как единственный способ.

Ту же компоненту переиспользуем на странице `/admin/car-photos/:carId`, чтобы не было двух разных механик.

## 2. Синхронизация админки и публичной части

- Форма создания/редактирования дополняется полями, которых сейчас нет в сохранении: цвет, мест, цена по городу/за город, мощность, расход, объём, депозит, VIN — всё уходит в `specs` (JSONB) и в колонки цен; проверяем, что `carsRepo` читает их обратно.
- Проверяем цепочку: сохранение → инвалидция кэшей `admin/cars` и `cars` → каталог `/cars`, карточка `/cars/:slug`, «Популярные модели» на главной.
- Гос.номер: остаётся в БД и в админке, но публичные server functions отдают карточку авто уже без `plate` (сейчас поле может уезжать в клиентский payload каталога) — вырезаем на сервере, а не прячем в вёрстке.
- Статусы: в проекте после миграции 006 три статуса — «Свободен», «Занят», «ТО» (мойка была удалена ранее). Проверяем, что «Занят» и «ТО» блокируют бронирование и на карточке, и в быстрой форме на главной, и на шаге оформления.
- Сквозной прогон: добавить авто с фото → каталог → карточка → бронирование → оплата (демо) → договор, без ошибок в консоли.

## 3. Редизайн админки

- `/admin` дашборд: KPI-карточки (брони сегодня, выручка сегодня, авто, клиенты) с иконками и приростом; блок «Статус автомобилей» цветными плашками со счётчиками; «Активные брони» карточками (фото авто, гос.номер, клиент, телефон, даты, сумма, бейдж оплаты); компактный календарь занятости с подсветкой занятых дат; «Последние клиенты» с инициалами-аватарами, числом заказов и рейтингом; блок быстрых действий.
- Форма авто: аккуратная сетка полей с подписями сверху, зона загрузки с превью, крупная кнопка «Сохранить», секции «Основное / Цены / Характеристики / Фото».
- Мобильная адаптация всех страниц админки (390×844): один столбец, карточки вместо таблиц, нижний таб-бар для основных разделов вместо бокового меню на узких экранах, sticky-шапка страницы.

## 4. Редизайн личного кабинета (/profile)

Светлые карточки с мягкими тенями и скруглениями:
- «Текущая аренда»: фото авто, бейдж «Активна», номер договора, даты выдачи и возврата, адрес выдачи (Доватора, 11) с кнопкой навигации, кнопка «Продлить аренду».
- Ниже: статус договора, документы (загружены/подтверждены), история бронирований карточками, рейтинг клиента звёздами.
- Гос.номер в кабинете не показываем.

## 5. Безопасность БД

- Никаких изменений типов `cars.images` и `cars.specs` — остаются JSONB; поле `plate` не трогаем.
- Если понадобится новая колонка — отдельный файл `db/migrations/012_*.sql` только с `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` и идемпотентными `update`; без `DROP COLUMN`.
- `migrations.server`: ошибка отдельной миграции логируется и не прерывает SSR — сейчас ошибка ловится на уровне всего прогона, доработаем до пер-миграционного `try/catch`, чтобы одна упавшая не блокировала остальные и приложение.
- Перед пушем покажу diff SQL-миграций отдельным сообщением.
