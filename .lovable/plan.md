# NSK-RENT: структура, бэкенд и выгрузка на сервер

## 1. Что есть сейчас (проверено по коду)

**Стек:** TanStack Start v1 (React 19, Vite 8, SSR через Node/Nitro-сборку), Tailwind v4, shadcn/Radix, TanStack Query, react-hook-form + zod, recharts, xlsx, embla, sonner.

**Маршруты (`src/routes/`):**
```text
/                      главная (NFS-сцена, гараж, FAQ, SEO-плитки)
/cars, /cars/$carId    каталог и карточка авто
/booking/$carId        бронирование
/payment/$bookingId    оплата (сейчас имитация)
/contract/$bookingId   договор + SMS-код (мок "123456")
/profile               личный кабинет
/blog, /blog/$slug     блог (markdown в коде)
/kei-cars, /rent/novosibirsk, /rent/bez-zaloga   SEO-лендинги
/privacy, /terms       юридические
/admin/login           вход по паролю (серверная сессия, cookie)
/_admin/admin/*        дашборд, авто, брони, клиенты, финансы, настройки
/robots.txt, /sitemap.xml, /api/public/version   служебные
```

**Бэкенд сегодня:** его почти нет. Единственные серверные функции — `src/lib/adminGate.functions.ts` (пароль админа, `ADMIN_PASSWORD` + `SESSION_SECRET`) и маршрут версии сборки. Все данные — моки: 22 авто в `src/data/mockCars.ts`, брони/клиенты/платежи/блог/FAQ в `src/mocks/*`. Черновик брони и избранное живут в `sessionStorage`/`localStorage` браузера. Базы данных, авторизации клиентов, приёма платежей и отправки писем нет.

**Домен:** в коде уже `https://nsk-rent.ru` (SEO, sitemap, canonical) — совпадает с выбранным боевым доменом.

## 2. Что делаем на этом этапе

### Шаг A. База данных PostgreSQL на вашем сервере
Схема (миграции SQL в репозитории, применяются командой при деплое):
- `cars` — автопарк (характеристики, цены, статус, галерея, slug)
- `car_photos` — фото авто
- `clients` — клиенты (телефон как логин, ФИО, e-mail, рейтинг, чёрный список)
- `client_documents` — паспорт/права + статус проверки
- `bookings` — брони (авто, клиент, даты, тариф, сумма, статус, договор)
- `payments` — платежи ЮKassa (id платежа, сумма, статус, способ)
- `otp_codes` — коды подтверждения телефона (хэш, срок, попытки)
- `admin_users` — сотрудники (позже вместо одного пароля)
- `content_pages` / `blog_posts` — при желании перенести блог в БД (можно отложить)

Данные из моков переносим сидом: 22 авто и справочники заливаются SQL-скриптом, фронтенд начинает читать из БД.

### Шаг B. Слой доступа к данным
Драйвер `postgres` (лёгкий, работает в Node-рантайме) + запросы в `*.server.ts`, наружу — серверные функции `*.functions.ts`. Публичные чтения (каталог, карточка авто, доступность дат) — без авторизации; всё, что меняет данные, — с проверкой сессии клиента или админа.

### Шаг C. Авторизация
- Клиент: вход по телефону + SMS-код, серверная httpOnly-сессия (тот же механизм, что уже работает в админке).
- Админ: остаётся пароль, но переносим на таблицу сотрудников с ролями (админ / менеджер).

### Шаг D. Интеграции
1. **ЮKassa (ИП).** Создание платежа при подтверждении брони, редирект на оплату, вебхук `/api/public/payments/yookassa` с проверкой подписи и IP, идемпотентная запись статуса, возвраты. Секреты: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`.
2. **SMS-коды.** Провайдер на выбор (SMS.RU / SMSC / Green SMS). Хранение хэша кода, срок 5 минут, лимит попыток и частоты запросов. Секрет: `SMS_API_KEY`.
3. **E-mail.** Уведомления клиенту (бронь, оплата, договор) и менеджеру (новая бронь). На своём сервере — SMTP вашего домена; секреты `SMTP_HOST/PORT/USER/PASS`.

### Шаг E. Подготовка сервера и деплой
Целевая схема на новом аккаунте Beget (VPS с Node 20+):
```text
nsk-rent.ru → nginx (SSL Let's Encrypt, gzip/brotli, кэш /assets)
            → Node-процесс приложения (systemd или pm2), порт 3000
            → PostgreSQL 16 (локально, доступ только с localhost)
```
Порядок работ:
1. Установить Node 20, PostgreSQL, nginx, certbot; создать пользователя приложения и каталог `/var/www/nsk-rent`.
2. Создать БД и пользователя, положить `.env` на сервере (права 600) со всеми секретами.
3. Настроить nginx: 301 с `rentsib.ru` и `www` на `https://nsk-rent.ru`, прокси на Node, выдача статики.
4. Автозапуск через systemd-юнит с рестартом при падении.
5. GitHub Actions (файл `.github/workflows/deploy.yml` уже есть, доработаем): сборка → `rsync` артефактов → применение миграций → рестарт → проверка `/api/public/version`. Секреты GitHub: `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `SSH_PORT`, `DEPLOY_PATH`, `RESTART_COMMAND`.
6. Бэкапы: ежедневный `pg_dump` по cron с хранением 14 дней.

Отдельно подготовлю текстовую инструкцию `DEPLOY.md` — пошагово, командами, чтобы выполнить на сервере копипастом.

## 4. Что нужно от вас

- Доступ к серверу (SSH) и подтверждение, что это VPS с правами root, а не шаред-хостинг: на шареде без Node сайт с SSR не запустится.
- Реквизиты ЮKassa (shopId и секретный ключ) — запрошу в защищённой форме, когда дойдём до шага 3.
- Выбор SMS-провайдера и ключ.
- Реальные реквизиты ИП (ФИО, ОГРНИП, ИНН) и контактный телефон/почта — сейчас в подвале заглушки.

## Технические детали

- Драйвер БД: `postgres` (postgres.js), пул на 10 соединений, запросы только в `*.server.ts`, чтобы серверный код не попал в клиентский бандл.
- Миграции: нумерованные SQL-файлы в `db/migrations`, применение маленьким скриптом `bun run db:migrate` на деплое, таблица `schema_migrations` для учёта применённых.
- Вебхук ЮKassa кладём в `src/routes/api/public/`, там проверка подписи и идемпотентность по `payment_id`.
- Целевой рантайм сборки надо перевести с Cloudflare-пресета на Node (`nitro preset: node-server`), иначе `.output` не запустится на VPS.
- Сессии: существующий механизм `useSession` из TanStack Start, cookie httpOnly + `SESSION_SECRET`.
