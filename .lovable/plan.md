# Компактный cookie-баннер и реальные оповещения админа

## 1. Cookie-баннер

- Уменьшить: узкая карточка (макс. ~360 px), одна строка текста, компактные кнопки «Только необходимые» / «Принять все», ссылки на политику мелким шрифтом.
- Позиция: левый нижний угол вместо ленты по всей ширине.
- Появление: плавный выезд слева с задержкой ~0.6 с, закрытие — обратной анимацией.
- На мобильном остаётся у левого края с безопасными отступами и не перекрывает нижнюю навигацию.

## 2. Реальные оповещения в админке

Сейчас колокольчик показывает выдуманный список. Заменим на настоящие события из базы.

События, по которым создаётся оповещение (полный набор):
- новая бронь;
- поступила оплата;
- отмена брони;
- возврат средств;
- автомобиль не возвращён вовремя;
- регистрация нового клиента.

Что будет в интерфейсе:
- колокольчик со счётчиком реально непрочитанных;
- список последних событий с датой и суммой;
- клик по строке открывает нужный экран: бронь — карточку брони, оплата/возврат — платежи, клиент — карточку клиента;
- «Прочитано» отмечается при клике, есть «Прочитать все»;
- список обновляется сам (опрос раз в 30 секунд).

## 3. Push на iPhone (PWA «на экран Домой»)

- В настройках админки — кнопка «Включить оповещения на телефон». Запрос разрешения только по нажатию и только когда сайт открыт как приложение с экрана «Домой» (требование iOS); иначе показываем подсказку, как добавить сайт на экран «Домой».
- Подписка устройства сохраняется в базе; push отправляется сервером на все подписанные устройства при каждом событии из списка выше.
- Нажатие на push открывает приложение сразу на нужной брони/платеже.
- Уведомление приходит, даже когда приложение закрыто (iOS 16.4+, значок с экрана «Домой»).

## Техническая часть

- Миграция `019_notifications.sql`: таблицы `admin_notifications` (тип, заголовок, текст, ссылка, `entity_id`, `read_at`, `created_at`) и `push_subscriptions` (endpoint, ключи p256dh/auth, метка устройства, `created_at`, `last_used_at`); индексы по `created_at` и `read_at`.
- `src/lib/notificationsRepo.server.ts` — создание/чтение/пометка прочитанного, очистка старше 90 дней.
- `src/lib/push.server.ts` — Web Push по стандарту VAPID (пакет `web-push`), отправка на все подписки, автоудаление подписок при ответах 404/410.
- Секреты `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`; публичный ключ отдаётся клиенту server function'ом. Без ключей push молча отключается, а внутриадминские оповещения продолжают работать.
- `src/lib/notifications.functions.ts` — защищённые админские функции: `listAdminNotifications`, `markNotificationRead`, `markAllRead`, `savePushSubscription`, `removePushSubscription`, `getVapidPublicKey`.
- Вызов `notifyAdmins()` встраивается в существующие места: создание брони (`bookings.functions.ts`), webhook ЮKassa (`api/public/yookassa-webhook.ts` — оплата и возврат), отмена/удаление брони, `autoAdvanceBookings` (просрочка возврата), регистрация клиента (`auth.functions.ts`). Дедупликация просрочки — по паре «бронь + тип».
- `public/push-sw.js` — сервис-воркер: показ уведомления и переход по ссылке в `notificationclick`; регистрируется только в админке.
- `AdminHeader.tsx` переводится на реальные данные (`useQuery`, `refetchInterval` 30 с), `src/mocks/notifications.ts` удаляется.
