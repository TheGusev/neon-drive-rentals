# Деплой, проверка админки на боевой БД и передаточный PDF

## Важное ограничение по доступу

Из среды Lovable нет SSH-доступа к вашему VPS и нет прав на push в `main` — эти два шага выполняете вы (или даёте доступ через GitHub Actions). Я готовлю всё, чтобы это делалось одной командой, и после вашего деплоя проверяю боевой сайт снаружи (HTTP-запросы, эмуляция iPhone, замеры скорости).

## 1. Подготовка деплоя

- Проверить `deploy/nginx-nsk-rent.conf` (gzip, HTTP/2, редирект www → apex, кэш `/assets/`) и добавить в него отдачу `Cache-Control` для фото и таймауты proxy.
- Добавить `deploy/DEPLOY.md`: пошагово — копирование конфига, `nginx -t`, reload, `git pull`, `bun install`, `bun run build`, `pm2 restart`, применение миграций (они выполняются автоматически при старте, включая новую `016_rental_journey.sql`).
- Добавить скрипт `deploy/deploy.sh` для повторяемого обновления боевого сервера.
- После вашего деплоя: внешняя проверка `nsk-rent.ru` — главная в мобильном виде, `/cars`, `/admin/login`, health-эндпоинт, наличие gzip/HTTP-2, время ответа.

## 2. Проверка админки на боевой БД

После деплоя прогоняю сценарии на реальной базе и фиксирую результат:

- Добавление авто с загрузкой фото с устройства → фото сохраняется в БД (bytea) и появляется на `/cars` и `/cars/:slug`.
- Замена/сортировка фото на странице фото авто, проверка, что публичная часть подхватывает изменения.
- Блок «Документы на проверку»: загрузка клиентом, подтверждение/отклонение админом, отражение статуса в кабинете.
- Конфликты дат: попытка брони на занятые даты блокируется и в публичной части, и в админке; статус авто «занят»/«ТО» снимает авто с бронирования.

Найденные расхождения исправляю в коде в том же заходе.

## 3. Вкладка «Брони» в админке

Раздел `/admin/bookings` уже есть; доработка:

- Свести статусы в единую понятную шкалу: Ожидает → Оплачена → Активна → Завершена → Отменена, с цветными бейджами и счётчиками по вкладкам.
- Автоперевод брони в активную аренду: при подтверждённой оплате и наступлении даты выдачи (или при выдаче ключей администратором) бронь становится «Активна», авто — «занято».
- Автозавершение: после приёма возврата бронь уходит в «Завершена», авто освобождается.
- Показ маршрута аренды в карточке брони (оплата, договор, ключи, возврат, отзыв) и кнопки действий для менеджера.
- Обновление данных в реальном времени: инвалидция кэша после каждого действия и авто-refetch списка.

## 4. PDF-документация для сдачи клиенту

Готовлю документ на русском (около 30–40 страниц) в `/mnt/documents`:

1. Обзор проекта, домен, окружения, что сделано по этапам.
2. Архитектура: TanStack Start (SSR), server functions, PostgreSQL, nginx, pm2.
3. Полная структура каталогов и назначение ключевых файлов.
4. Все зависимости с пояснением зачем каждая.
5. База данных: все таблицы, поля, связи, список миграций 001–016.
6. Backend: server functions по модулям (авто, брони, платежи, профиль, отзывы, админ), правила доступа, авторизация админа и клиента.
7. Публичная часть: маршруты, SEO, темы, изображения и производительность.
8. Админка: подробное руководство пользователя — вход, дашборд, авто и фото, брони и статусы, клиенты, документы, финансы, настройки.
9. Личный кабинет клиента и полный путь аренды.
10. Оплата (ЮKassa), SMS-подтверждение, договор.
11. Эксплуатация: деплой, бэкапы, мониторинг, что делать при сбое.
12. Итоговая проверка соответствия: чек-лист «заявлено — реализовано — статус».

Перед выдачей PDF каждая страница проверяется визуально на переносы, обрезку текста и пустые страницы.

## Технические детали

- Генерация PDF — скриптом на Python (reportlab) с фирменными цветами NSK-RENT, кириллическим шрифтом и оглавлением.
- Проверка боевого сайта — Playwright (эмуляция iPhone) плюс curl для заголовков и таймингов.
- Автоперевод статусов реализуется на стороне server functions/репозитория, чтобы работало и без открытой админки.
