# Полноценная бронь + аккаунты клиентов + выкатка на nsk-rent.ru

## 1. Бронирование → форма оплаты → ЮKassa

Сейчас после выбора дат идут два отдельных экрана (`/payment/:id` — только выбор способа, `/contract/:id` — контакты, SMS, создание брони). Бронь создаётся лишь в самом конце, часть клиентов до него не доходит.

Станет: один экран оплаты после выбора дат и авто.

- `/payment/:draftId` — единая форма: сводка (авто, даты, тариф, итог с залогом), контакты (имя, телефон, e-mail), способ оплаты (карта / СБП), согласия, SMS-код подтверждения договора.
- Кнопка «Оплатить»: отправляет код → после подтверждения сохраняет бронь в БД (`createBooking`) → создаёт платёж (`startPayment`) → переводит на страницу оплаты ЮKassa. Если ЮKassa в тестовом режиме — бронь сразу помечается оплаченной и клиент попадает в кабинет.
- Если клиент вошёл в аккаунт, поля контактов подставляются автоматически и бронь привязывается к его учётной записи.
- `/contract/:id` остаётся как страница просмотра и скачивания договора по уже созданной брони (ссылка из кабинета и админки), а не как шаг оформления. Старый URL шага перенаправляет на оплату.
- Ошибки показываются списком, кнопка не «молчит»: любые сбои сети/ЮKassa выводятся текстом.

## 2. Регистрация клиента по e-mail и паролю

Регистрация по желанию: бронировать можно гостем, аккаунт предлагается после оплаты.

- Новая миграция: у клиентов появляются `email` (уникальный, без учёта регистра), `password_hash`, `email_verified_at`, индекс по телефону.
- `/register` — форма: имя, e-mail, телефон, пароль (минимум 8 символов) + повтор. Если клиент с таким телефоном уже есть (бронировал гостем), аккаунт привязывается к нему — история броней сразу видна.
- `/login` — две вкладки: «E-mail и пароль» и текущий вход по SMS-коду. Плюс ссылка «Забыли пароль» → сброс по SMS-коду на телефон аккаунта.
- Пароли хранятся хешем (scrypt из встроенного `node:crypto`, соль на пользователя), сессия — существующая httpOnly-кука клиента. Ограничение попыток входа, чтобы пароль нельзя было подобрать.
- После успешной оплаты гостю показывается блок «Создайте пароль, чтобы отслеживать аренду» — один шаг, телефон уже известен.
- Кабинет `/profile` перестаёт зависеть от моков: профиль, брони, документы, отзывы и избранное берутся по `clientId` из сессии; для гостя — приглашение войти. В админке в карточке клиента видно, есть ли у него аккаунт.

## 3. Сборка и выкатка на боевой домен

- Локально: сборка и типы, прогон сценария «даты → оплата → бронь в БД → кабинет» и «регистрация → вход → кабинет» на локальной базе.
- Миграции применяются автоматически при первом запросе на сервере, отдельных действий не требуется.
- Изменения уходят в `main`, GitHub Actions собирает и выкладывает на nsk-rent.ru, затем проверяются `/api/public/version` и `/api/public/health`.
- После выката проверю на боевом домене: каталог, оформление брони, кабинет клиента, вход в админку, отображение новой брони в админке.

## Технические детали

- Файлы: `src/routes/_public.payment.$bookingId.tsx` (переписывается в единую форму), `_public.contract.$bookingId.tsx` (режим просмотра), `_public.login.tsx`, новый `_public.register.tsx`, `_public.profile.tsx`.
- Серверная часть: `src/lib/auth.functions.ts` (+ регистрация, вход по паролю, сброс), новый `src/lib/password.server.ts`, `src/lib/clientsRepo.server.ts` (поиск по e-mail, привязка пароля), `src/lib/bookings.functions.ts` (привязка брони к `client_id` из сессии), `src/lib/profile*.ts`.
- Новая миграция `db/migrations/015_client_accounts.sql`, регистрация в `src/lib/migrations.server.ts`.
- Секреты на сервере не меняются, кроме уже существующих `SESSION_SECRET`, `DATABASE_URL`, ключей ЮKassa и SMS.
