# Скорость загрузки nsk-rent.ru + рабочий личный кабинет на реальных данных

## Что показала проверка боевого домена (сделано до плана)

- Сервер отвечает быстро: главная — TTFB 0.31 с, HTML 116 КБ, `/api/public/health` → `ok: true`, база доступна, 21 авто, таблицы на месте. То есть «долго грузится» — не про сервер и не про базу.
- Главная тянет **48 modulepreload-чанков и ~810 КБ JS+CSS** до первой отрисовки. Это и есть основная причина долгого «белого экрана», особенно на мобильном интернете.
- Фото не оптимизированы: только JPEG, без WebP/AVIF и без адаптивных размеров; в `public/assets` и `src/assets` лежит по ~9 МБ фотографий, отдельные файлы до 184 КБ. Ленивая загрузка ниже первого экрана не выставлена системно.
- Личный кабинет наполовину демонстрационный: имя клиента, рейтинг, отзывы и документы берутся из `src/mocks/profile.ts`, а не из базы. Реальны только брони (`getMyBookings`) и вход по SMS.

## 1. Мгновенная загрузка

1. Сократить стартовый JS: в основной чанк главной попадают компоненты, нужные только после действия пользователя. Переводим на подгрузку по требованию меню, шторку брони, диалоги подтверждения, галереи и FAQ-аккордеон; проверяем, что тяжёлые библиотеки (календарь, `xlsx`, графики) не попадают в чанк главной.
2. Уменьшить число предзагружаемых чанков: убрать агрессивный preload второстепенных маршрутов, оставить preload только для реально критичных ресурсов первого экрана.
3. Фото: сгенерировать WebP-версии всего парка и отдавать `<picture>` с JPEG-фолбэком, задать ширину/высоту (без «прыжков» вёрстки), `loading="lazy"` + `decoding="async"` для всего, что ниже первого экрана, и приоритетную загрузку только для главного фото героя.
4. Кэширование на сервере: длинный immutable-кэш для файлов с хэшем в имени и разумный кэш для фотографий парка.
5. Скелетоны вместо пустоты: пока подгружается блок, показываем лёгкий каркас, чтобы страница ощущалась мгновенной.

## 2. Личный кабинет на реальных данных

1. Профиль клиента: имя, телефон, дата регистрации и рейтинг берутся из таблицы `clients` по текущей сессии, а не из моков.
2. Документы: новая таблица документов клиента (паспорт/права, статус проверки, файл), загрузка через тот же надёжный механизм, что и фото авто, с сохранением в постоянную папку; статусы «на проверке / проверено / отклонено» проставляет админ.
3. Отзывы и рейтинг: новая таблица отзывов, привязанная к брони; рейтинг клиента считается из базы. Пустое состояние — честное («отзывов пока нет»), без выдуманных данных.
4. История броней и текущая аренда уже реальны — дополняю их фото авто из базы, номером договора и ссылками на оплату/договор.
5. Избранное: сохраняем за клиентом на сервере, чтобы список не терялся при смене устройства.
6. В админке — раздел проверки документов клиентов (одобрить/отклонить), чтобы цикл был замкнут.

## 3. Сквозная проверка «БД → бэкенд → фронт»

- Прогон всех страниц каталога, карточки авто, брони, оплаты, договора, кабинета и админки на локальной базе с реальными данными.
- Замер до/после: вес JS первого экрана, количество запросов, время до отрисовки на профиле iPhone с медленной сетью.
- Проверка боевого домена после выката: `/api/public/health`, главная, каталог, кабинет.

## Технические детали

- Разбиение бандла: `React.lazy` + `Suspense` для `NfsSideMenu`, шторки брони, `BookingConfirmDialog`, `CarQuickView`, `FaqBlock`; ревизия `modulepreload` в `src/router.tsx` (`defaultPreload`) и в маршрутах.
- Изображения: скрипт генерации WebP в `public/assets/cars/`, обновление `CarImage.tsx` на `<picture>` + `srcset`, явные `width`/`height`, `fetchpriority="high"` только у героя.
- Миграция `013_client_profile.sql` (только `create table if not exists` / `add column if not exists`): `client_documents`, `client_reviews`, `client_favorites`; `clients` дополняется `name`, `rating` считается запросом.
- Серверные функции в `src/lib/clientsRepo.server.ts` и новом `src/lib/profile.functions.ts`: `getMyProfile`, `getMyDocuments`, `uploadClientDocument`, `getMyReviews`, `toggleFavorite`; всё через существующую клиентскую сессию.
- `src/mocks/profile.ts` перестаёт использоваться в UI кабинета.
- Не трогаю: вход в админку, `.env`, серверные переменные, типы `images`/`specs`, поле `plate`, формулы цен и логику доступности.
