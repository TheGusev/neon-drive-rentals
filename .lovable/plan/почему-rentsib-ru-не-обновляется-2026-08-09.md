# Почему rentsib.ru не обновляется

## Что подтверждено

- Скриншот истории коммитов в GitHub: последние коммиты пришли «1m» и «2m» назад, есть вчерашний «Убрал сдвиг блоков в CSS». Значит связка **Lovable → GitHub работает**, свежий код в репозитории есть.
- `https://rentsib.ru/` отвечает 200 (nginx), но отдаёт **старую сборку**:
  - заголовок «… | RentSib» — бренд до переименования в NSK-RENT,
  - `og:url` = `https://neon-drive-rental.lovable.app`,
  - в `sitemap.xml` все `<loc>` тоже `neon-drive-rental.lovable.app`,
  - в описании ещё есть «Доставка в Толмачёво», хотя доставку мы убрали,
  - `/robots.txt` отвечает 404 — маршрут, добавленный позже, на сервере отсутствует.
- В текущем коде: `SITE_URL = https://nsk-rent.ru`, бренд NSK-RENT, единый пункт выдачи «Доватора, 11», маршрут `robots.txt` есть.
- В репозитории **нет** `.github/workflows` — автоматической сборки и выкладки из GitHub не существует.

Вывод: код свежий и в Lovable, и в GitHub. Рвётся звено **GitHub → сервер**: сборка на rentsib.ru примерно от 6 августа, значит на сервере не выполняется (или падает) `git pull` + `build` + перезапуск Node-процесса.

## Что предлагаю сделать

1. Добавить GitHub Actions workflow деплоя `.github/workflows/deploy.yml`: сборка на CI и выкладка на сервер по SSH с перезапуском процесса. Это заменяет неработающий ручной/скриптовый деплой на сервере на воспроизводимый автоматический.
2. Добавить маршрут `/api/public/version`, отдающий идентификатор коммита и время сборки — чтобы за секунду проверять, обновился ли сервер после деплоя.
3. Продублировать этот идентификатор мета-тегом в HTML, чтобы «свежесть» страницы читалась прямо из ответа сайта.

## Технические детали

- Workflow: `checkout` → `bun install --frozen-lockfile` → `bun run build` → `rsync` артефактов (`.output`) на сервер → рестарт процесса (`pm2 reload` или `systemctl restart`).
- Секреты в GitHub Secrets: `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `DEPLOY_PATH`, имя сервиса/процесса. Их нужно будет добавить вам — из кода я их задать не могу.
- Маршрут версии — server route в `src/routes/api/public/version.ts`, возвращает JSON `{ commit, builtAt }` из переменных сборки.

## Что нужно от вас

Скажите, как сейчас устроен деплой на Beget: вебхук, cron с `git pull`, ручной SSH или панель хостинга — и путь к проекту на сервере. Если проще, можно сразу перейти на CI-деплой по пункту 1: тогда я подготовлю workflow, а вы добавите SSH-секреты в GitHub.
