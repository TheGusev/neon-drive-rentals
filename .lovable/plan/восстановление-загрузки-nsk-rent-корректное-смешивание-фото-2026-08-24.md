# Восстановление загрузки NSK-RENT, корректное смешивание фото и полный PDF по проекту

## Подтверждённая причина

- Сам сайт сейчас отвечает `200` на `/`, `/cars` и `/api/public/version`, поэтому это не общий 404/падение веб-сервера.
- Карточки получают из PostgreSQL старые сборочные адреса наподобие `/assets/honda-n-wgn-grey-Dsdj--MY.jpg`; на preview и `nsk-rent.ru` такой файл отвечает `404`. Стабильные адреса `/assets/cars/...` и `/assets/cars/real/...` отвечают `200`.
- Миграция `010_real_photos.sql` заменила массивы `images` у четырёх автомобилей. Требовалось не заменять прежние кадры, а добавлять реальные фотографии в существующие галереи.
- Корневой загрузчик приложения ждёт каталог и публичные бронирования до показа любой страницы. При медленной или временно недоступной БД это визуально выглядит как незагружающийся сайт и затрагивает одновременно мобильную и ПК-версию.

## 1. Срочно восстановить показ сайта

- Убрать единую точку отказа: публичная часть должна открываться даже при таймауте PostgreSQL.
- Добавить ограниченный таймаут запросов каталога/броней и безопасный публичный fallback: каталог берётся из локального набора, занятость временно считается пустой; ошибки остаются в серверном журнале.
- Не скрывать ошибки в админке: административные операции по-прежнему должны явно сообщать, что БД недоступна, а не работать с моками как с настоящими данными.
- Оставить текущую логику входа в админку, `.env` и секреты без изменений.
- Проверить стартовую загрузку без БД, с медленной БД и при обычном подключении.

## 2. Починить все фотографии и сохранить старые

- Создать новую миграцию после `010` — уже применённую миграцию не переписывать.
- Для всех 21 записей заменить устаревшие Vite-хешированные URL на стабильные `/assets/cars/...`.
- Для автомобилей с реальными снимками объединить галерею в нужном порядке: реальный кадр как обложка только там, где точно совпадают модель/цвет; прежние уникальные изображения оставить следующими кадрами.
- Для общих кадров площадки, приборки и машин на фоне оставить отдельный блок «Живые фото парка» и подходящие статьи блога; не выдавать их за фото конкретной машины.
- Синхронизировать PostgreSQL и `mockCars.ts`, чтобы сайт одинаково выглядел с БД и в аварийном режиме.
- Добавить единый обработчик ошибки изображения: при `404` карточка автоматически показывает стабильное резервное фото конкретного автомобиля, а не пустой блок или общий знак вопроса.
- Не удалять ни старые сгенерированные, ни ранее добавленные реальные изображения; удалить можно будет только подтверждённые дубли после полного перечня.

## 3. Ускорить мобильную и ПК-загрузку

- Не загружать сразу десять полноразмерных фото гаража в режиме `eager`: приоритет оставить только первому видимому кадру, остальные загружать по мере приближения к области просмотра.
- Оптимизировать тяжёлые JPG в WebP/AVIF с сохранением исходников и стабильных путей; задать корректные размеры, чтобы карточки не прыгали.
- Добавить понятные skeleton/error-состояния для каталога и блока гаража, чтобы медленная сеть не воспринималась как зависание.
- Сохранить ленивую загрузку формы бронирования и проверить, что её отдельный чанк открывается повторно после сетевого сбоя.

## 4. Проверка результата

- Автоматически пройти главную, обе страницы каталога и все 21 карточки автомобиля.
- Для каждого `<img>` проверить HTTP-статус, `complete`, `naturalWidth`, основной кадр и переключение галереи.
- Проверить отсутствие повторов одной обложки у разных записей, но разрешить общие кадры только внутри галереи одного авто или блока живых фото.
- Прогнать мобильный WebKit/iPhone и desktop Chromium при обычной сети и throttling: страница должна отрисоваться, меню открыться, гараж прокручиваться, каталог и карточки загружаться без hydration/page errors.
- Проверить `nsk-rent.ru` после публикации через `/api/public/version`, главную, каталог и прямые URL изображений.

## 5. Один полный PDF-файл по устройству проекта

Подготовить русскоязычный документ с оглавлением и схемами:

1. Назначение проекта и пользовательские сценарии.
2. Полное дерево значимых каталогов и файлов.
3. Frontend: TanStack Start/Router, React Query, маршруты, layouts, компоненты, темы, состояние, формы, каталог, бронирование, профиль и админка.
4. Backend: `createServerFn`, серверные репозитории, обработка ошибок, загрузка файлов, публичные API-маршруты.
5. PostgreSQL: таблицы, связи, статусы, миграции `002–011`, откуда берутся автомобили, брони, клиенты и платежи.
6. Полный поток данных:

```text
Браузер → маршрут/React Query → server function → repository → PostgreSQL
        ← JSON/SSR             ← mapping         ← строки БД
```

7. Изображения: исходники, стабильные публичные URL, БД `cars.images`, fallback, админ-загрузка и правила смешивания реальных/старых фото.
8. Авторизация админки и границы безопасности — без раскрытия значений секретов.
9. ЮKassa: создание платежа, webhook, статусы и необходимые переменные окружения.
10. Сборка и деплой: GitHub Actions → `.output` → VPS → restart → проверка версии; Nginx/HTTPS/статика/персистентный каталог загрузок.
11. Таблица переменных окружения только с назначением и местом настройки, без значений.
12. Резервное копирование, восстановление, диагностика 404 фото, недоступности БД, 500 и расхождения версии.
13. Чек-листы запуска, обновления и аварийного восстановления.

PDF будет сохранён как отдельный скачиваемый артефакт. После генерации каждая его страница будет преобразована в изображение и визуально проверена на обрезанный текст, перекрытия, пустые страницы и читаемость.

## Технические детали

- Новая миграция будет идемпотентной и будет объединять JSONB-массивы без дублей, а не заменять их вслепую.
- Старые хешированные URL будут нормализованы на серверной границе, чтобы уже повреждённая строка БД не ломала интерфейс до применения миграции.
- Пользовательские загрузки из админки необходимо хранить вне каталога `.output`, иначе `rsync --delete` при следующем деплое удалит их; в PDF будет указан безопасный постоянный каталог и настройка `PUBLIC_ASSETS_DIR`.
- Финальный отчёт перечислит найденные причины, изменённые файлы, результат тестов и ссылку на PDF.
